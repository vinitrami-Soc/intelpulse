Privacy

What this server keeps, and for how long

IntelPulse is self-hosted: whoever runs this server decides where it runs and who may join. This page says what the software stores and sends. For anything about this particular server (its backups, its logs, the law it operates under), ask its owner.

Your account

  • Your username, display name and, if you give one, your email address. The address is used only to confirm it and to send a password reset link, and only when the server has email set up.
  • Your password, as an argon2id hash: the server cannot read it back.
  • One cookie, ip_session, which keeps you signed in. It cannot be read by scripts, is not sent with requests from other sites, and ends after 8 hours without use or 7 days at most. Signing out ends it.

Your cases

WhatHow it is keptFor how long
What a case was made from: the paste, the uploaded file's text, a pushed alert's description and evidence Sealed with AES-256-GCM under the server's key; read by the analyst who made the case and the workspace's admins (a pushed alert's text by the whole team) The workspace's retention period, 30 days unless an admin sets 1 to 365. An admin can hold a case to keep it longer, and the analyst or an admin can delete it sooner
The verdict, the indicators, what each source answered, the case's status, assignee and ticket In the workspace's database, seen only by its members Until an admin deletes the case
The audit log: who did what, and when Hash-chained, so an edited or removed record shows Kept. When a case is deleted, the log keeps its ID and a fingerprint (SHA-256) of its input, not the input
Provider keys and tracker credentials Sealed with AES-256-GCM; the console shows only their last four characters Until an admin removes them

No workspace can read another's cases, settings or audit records, and the server's owner does not see a workspace's cases from the Server pane.

What leaves the server

  • Indicators, to the sources your workspace turned on. To check an IP address, a domain, a URL or a hash, the server sends that indicator, and only that, to the providers enabled in Settings (AbuseIPDB, AlienVault OTX, GreyNoise, ThreatFox, URLhaus), with the workspace's own key where one is needed. Their answers are cached for 24 hours, and an answer fetched with your workspace's key is cached for your workspace only. The offline feeds are looked up on the server and send nothing.
  • A ticket, to the tracker an admin set up. Filing a ticket sends it to that workspace's Jira or ServiceNow.
  • Email, if the server sends any. An address confirmation or a reset link, through the mail server its owner configured.

The pages load nothing from another site: no analytics, no advertising, no fonts or scripts from a third party.

Logs

Each request is logged with its method, path, status, time taken and the client's address, and API keys are masked out of every log line. How long the logs are kept is up to the server's owner.

In this browser

The console remembers your theme (light or dark). On a server it keeps none of your cases in the browser. The public demo keeps its own sample triages and allow and block lists in this browser's storage, and what you paste into it never leaves the browser.
