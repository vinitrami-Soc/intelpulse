One alert in, one verdict and its evidence out

IntelPulse reads the indicators in an alert, a log or a paste, asks every intelligence source your workspace has turned on about each of them in one pass, and gives back a score for each indicator with the arithmetic behind it, a verdict for the case, and a ticket for Jira or ServiceNow.

What it does with an alert

  • Finds the indicators. IP addresses, domains, URLs, file hashes, email addresses and CVEs, in plain lists, firewall and proxy syslog, Windows events as JSON or a SIEM export, defanged (1.2.3[.]4, hxxp://) or not. Private and reserved addresses are dropped before anything is looked up.
  • Asks every source at once. AbuseIPDB, AlienVault OTX, GreyNoise, ThreatFox and URLhaus with your workspace's own keys, and the offline feeds the server keeps: Feodo Tracker, FireHOL, the ThreatFox dump, CISA's known exploited vulnerabilities, NVD and GeoLite2. A source that fails or has no key is shown as such.
  • Shows its arithmetic. Each score is a weighted mean of the sources that answered, raised by the most authoritative single hit, and the weights are published (the scoring model (opens GitHub in a new tab)).
  • Says what changed. An indicator seen before is compared with the last time: a new source flagging it, a score that moved.
  • Writes the ticket. Severity and priority, a summary, the evidence for each indicator, the ATT&CK techniques and the containment steps, in Markdown or JSON, or filed in Jira or ServiceNow.

For one analyst or a whole SOC

  • Workspaces. Sign up just for yourself or for your organization. A workspace sees only its own cases, indicators, settings and audit records.
  • A team. Admins invite members, set roles (admin or analyst), keep the providers' keys and the trackers' credentials, and make API tokens that can only read, triage, or push alerts.
  • A case workflow. Every case has a status, an assignee and a closing reason; the queue orders open cases by priority, and the history searches all of them.
  • Pushed alerts. A SIEM or an EDR posts its alert to /api/alerts and gets a triaged case back.

Built to hold alert text

  • What a case was made from (the paste, the uploaded file, a pushed alert's description and evidence) is sealed with AES-256-GCM and deleted after the workspace's retention period, 30 days unless an admin sets another.
  • Every change is recorded in a hash-chained audit log that can prove it has not been edited.
  • Passwords are hashed with argon2id, sessions are protected against cross-site requests, sign-in slows down after wrong passwords, and each workspace has a daily triage budget.
  • The pages and the API come from one server, with a strict content security policy: no script, font or tracker from anywhere else.

What it does not do: it does not block, quarantine or change anything. It reads and reports, and a person decides.

Run it yourself

IntelPulse is open source under the MIT licence. One docker compose up runs it with Postgres and Redis; the README (opens GitHub in a new tab) explains the setup. The public demo runs entirely in your browser, on synthetic data.

Sample data on the demo uses RFC 5737 addresses and RFC 2606 names only.
