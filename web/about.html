About

Built for the analyst with forty alerts in the queue

IntelPulse is an open-source threat intelligence workbench. It reads the indicators in an alert, asks every intelligence source a workspace has turned on about each of them at once, and gives back a verdict with the arithmetic behind it. It is built and maintained by Vinit Rami, under the MIT licence.

Try the demo Read the code (opens GitHub in a new tab)

Why it exists

An alert names a handful of indicators. Checking each by hand means pasting it into five or six vendor sites, weighing what each one said in its own format, and writing it up: about twenty minutes an alert, at forty alerts a shift. That is where triage time goes, and where an indicator gets missed, because the fifth tab is the one skipped at 3 a.m. IntelPulse does that pass in one request, and shows its working.

What it holds to

  • Show the arithmetic. Every score opens to what each source said, how much it counts, and the sum. A verdict nobody can explain is a verdict nobody should act on.
  • A source that is down is not a clean source. A lookup that timed out is left out of the score rather than counted as a pass, and the confidence says how much of the picture answered.
  • Private by design. Alert text is sealed and deleted on a schedule, nothing loads from another host, and an indicator goes only to the sources a workspace turned on. The privacy page lists what is kept.
  • Yours to run. A server is one script to set up, with no account anywhere but on it.
  • Measured, not claimed. 1,144 automated checks run on every change, and the extraction benchmark says plainly that its test corpus is the project's own.

Who builds it

IntelPulse is written by Vinit Rami (opens in a new tab), who builds defensive security tools with an offensive-security background. Its sibling, PhishHawk (opens GitHub in a new tab), triages reported phishing email.

Get in touch

  • A wrong verdict, a bug or an idea: open an issue (opens GitHub in a new tab). A verdict you think is wrong is the most useful report there is.
  • A security issue: report it privately, as the security policy (opens GitHub in a new tab) asks, never in a public issue.
  • Code: contributions are welcome, and CONTRIBUTING.md (opens GitHub in a new tab) says how.
